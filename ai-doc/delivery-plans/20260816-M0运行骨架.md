# M0 运行骨架需求交付记录

## 1. 需求背景

协序需要以单一 Docker Compose 交付 Web 应用，用户不额外安装 Rust、Node、Codex 或宿主机 Runner。M0 先建立可验证的 Server、Web、PostgreSQL、迁移和 Runner 运行基础，为后续任务与 Agent 功能提供稳定入口。

## 2. 交付内容

- 创建 Rust workspace、Server、Runner、迁移程序和分层 crate 占位。
- 创建 React + TypeScript + Vite Web Shell，并接入已确认的模块入口。
- 创建 PostgreSQL 16 Compose 服务、迁移服务、Server 服务和 Runner 服务。
- 实现 `/healthz`、`/readyz`、Runner heartbeat 和 M0 数据表。
- 增加 Web 深链接回退、移动端模块切换和看板窄屏布局。
- 增加 `.env.example`、Dockerfile、`.dockerignore` 和运行说明。

## 3. 技术方案

- 后端：Rust、Axum、Tokio、tokio-postgres。
- 前端：React、TypeScript、Vite。
- 数据库：PostgreSQL 16。
- 运行方式：Docker Compose；Server 托管 Web 静态资源，Runner 独立运行。
- M0 不引入 Redis、Git、worktree 或真实 Codex 执行。

## 4. 影响范围

- 新增 `/Volumes/Tools/workspace/task-relay/xiexu/apps`、`crates`、`Cargo.toml`、`Dockerfile`、`compose.yaml` 等源码与配置。
- 新增 `schema_migrations`、`runner_instances` 两张 M0 基础表。
- 创建 Docker Volume：PostgreSQL 数据、托管工作区和产物目录。
- 不修改 relay 或 dashi-taskboard 源码，也不要求目标目录成为 Git 仓库。

## 5. 验证结果

- `npx tsc --noEmit`：通过。
- `npm run build`：通过。
- `docker compose -f compose.yaml config`：通过。
- `docker compose -f compose.yaml build`：通过。
- `docker compose -f compose.yaml run --rm migrate`：通过，重复迁移幂等。
- `docker compose -f compose.yaml ps`：PostgreSQL 与 Server healthy，Runner running。
- `curl http://127.0.0.1:8080/healthz`：返回 `{"status":"ok"}`。
- `curl http://127.0.0.1:8080/readyz`：返回数据库和迁移均 ready。
- PostgreSQL 查询：`runner-1|ready`。
- Web 深链接 `/project/xiexu`、`/workflow/demo`：HTTP 200。

限制：宿主机没有 Rust 工具链，因此 Rust 编译通过 Docker `rust:1.85-slim-bookworm` 完成；M0 尚未执行真实 Codex 任务。

## 6. 交付价值

用户现在可以用一个 Compose 配置启动协序 Web 骨架，验证数据库迁移、服务就绪、Runner 存活和 Web Shell，不需要额外安装开发运行时。后续 M1 可以在稳定运行底座上接入任务与评论垂直切片。
