# M1 任务域基础版 需求交付记录

## 1. 需求背景

在 M0 Docker/Web 运行骨架上，建立协序统一任务面板和项目空间共享的任务事实源，为后续 Agent 执行和工作流任务接入提供稳定的数据边界。

## 2. 交付内容

- 项目 CRUD（不提供物理删除）。
- 任务创建、编辑、父子任务关系和看板阶段状态机。
- Todo 方案确认开关，M1 默认开启。
- 任务评论和任务事件时间线。
- 依赖关系、项目文档及版本存储基础表。
- 真实 API 驱动的任务看板：拖拽移动、父子标记、评论入口和方案确认开关。
- M0 Runner heartbeat 保持兼容，但 M1 不接入业务执行作业。
- Compose 部署收敛为 `postgres` + `app` 两个容器，`app` 内部运行 migrate、server、runner。

## 3. 技术方案

- Rust/Axum HTTP API，PostgreSQL 唯一事实源。
- 迁移版本 `0002_m1_task_domain`，重复运行幂等并兼容已有 M0 数据卷。
- 服务端使用 `xiexu-domain` 的 `BoardStage` 和状态转换校验，前端不直接写入阶段。
- 评论的 `intent` 仅作为非可信提示保存，AI 语义解释延后到后续执行里程碑。
- 前端使用 React/TypeScript，复用 M0 taskboard 风格 Web Shell。

## 4. 影响范围

- `apps/server/src/main.rs`
- `apps/migrate/src/main.rs`
- `crates/domain/src/lib.rs`
- `apps/web/src/main.tsx`
- `apps/web/src/styles.css`
- workspace Cargo 依赖和 M1 文档/迁移

明确不包含：真实 Codex、Runner 业务 job、Todo 周期扫描、Agent 记忆、工作流画布、AI 评论理解、权限、Redis、Git/CodeGraph 初始化。

## 5. 验证结果

- `npx tsc --noEmit`：通过。
- `npm run build`：通过。
- `docker compose -f compose.yaml config`：通过。
- `docker compose -f compose.yaml build`：通过；Rust server、runner、migrate 与 Web 构建成功。
- `docker compose -f compose.yaml up -d`：通过；PostgreSQL healthy，server healthy，runner 正常运行。
- `curl -fsS http://localhost:8080/readyz`：返回 `{"status":"ready","database":"up","migration":"ready"}`。
- API smoke：项目、父子任务、阶段转换、评论和事件查询成功；`children_count` 正确，M1 评论不自动应用状态转换。

限制：宿主机没有 Rust 工具链，Rust 编译通过 Docker 完成；目标目录不是 Git 仓库且无 CodeGraph 索引，使用 bounded fallback 检查。

## 6. 交付价值

任务面板和项目空间现在可以围绕同一份持久化任务数据工作，状态、评论和事件均可追溯，并为 M2 执行底座保留清晰边界。

## 7. 虚拟团队协作

- PM：审查 M1 产品边界和明确排除项。
- SA：审查数据模型、状态机和 M1/M2 边界，明确不提前接入 Runner 业务作业。
- TPM：输出 M1 实施拆解和验收标准。
- 主协调者：完成源码、迁移、Web 接入与 Docker/API 验证。
