# M2 执行控制面需求交付记录

## 1. 需求背景

将任务看板的处理中阶段接入可追踪执行链路，为后续 Agent、Codex 和工作流执行提供统一的作业、尝试、租约、事件和输出事实源。

## 2. 交付内容

- 新增执行作业、执行尝试、执行事件和运行输出数据表及幂等迁移。
- 进入 `in_progress` 时在阶段转换事务内创建 `execute_task` 作业和去重键。
- Runner 支持数据库行锁领取、30 秒租约、尝试计数、租约过期重新排队和受控成功/失败记录。
- 新增 `GET /api/tasks/:task_id/execution`，聚合返回 jobs、attempts、events 和 outputs。
- Runner 周期扫描需要方案确认的 Todo，生成 `prepare_task_plan` 并在受控完成后推进到 `plan_review`。
- 方案确认、验收通过和返工评论经过服务端状态机校验后分别推进执行、完成和重新执行。
- 受控作业成功后把任务推进至 `acceptance`，并写入任务时间线和执行摘要。
- 任务详情展示运行输出和执行事件数量。
- Runner 接入镜像内固定版本 `codex-cli 0.147.0`，支持 `controlled/real` 两种模式、非交互 JSONL 输出、超时、工作区边界、敏感环境排除和 Codex thread ID 记录。
- Compose 增加 `CODEX_HOME` 命名 Volume；Server 增加 `GET /api/runtime/codex`，仅返回安装、版本、模式和认证布尔值。
- 执行失败按 1 分钟、5 分钟退避重试，默认最多三次总尝试；attempt 保存失败信息和 Codex thread ID。
- 保持单个 `xiexu-app` 容器内运行迁移、Server 和 Runner，PostgreSQL 继续独立运行。

## 3. 技术方案

Server 使用 Rust/Axum 与 PostgreSQL 事务；Runner 使用 Tokio + tokio-postgres，以 `SELECT ... FOR UPDATE SKIP LOCKED` 实现并发安全领取。作业状态与任务执行状态在关键步骤使用同一事务更新，执行输出作为独立索引保存。

## 4. 影响范围

- `apps/migrate`：新增 `0003_m2_execution_control` 结构。
- `apps/server`：阶段转换入队、评论驱动状态转换和执行记录查询 API。
- `apps/runner`：心跳、Todo 扫描、方案作业、领取、租约、受控执行和失败记录。
- `apps/runner/Cargo.toml`：增加 `serde_json` 依赖。
- `README.md`、`ai-doc/m2-execution-control-baseline.md`：更新运行边界和交付说明。

本轮已完成真实 Codex CLI 适配，但默认仍为 `controlled`；权限管理仍不进入 MVP，项目源码目录绑定和自然语言 AI 评论理解也未完成。周期扫描已实现为 Runner 对 Todo 的方案作业扫描。

## 5. 验证结果

- `npm run build && npx tsc --noEmit`：通过。
- `docker compose -f compose.yaml build`：通过，三个 Rust 二进制和 Web 均构建成功。
- `docker compose -f compose.yaml up -d --remove-orphans`：通过，仅保留 `xiexu-app`、`xiexu-postgres` 两个容器，应用健康。
- `curl http://localhost:8080/readyz`：返回 `{"status":"ready","database":"up","migration":"ready"}`。
- `docker run --rm --entrypoint codex xiexu-app --version`：返回 `codex-cli 0.147.0`。
- `curl http://localhost:8080/api/runtime/codex`：返回已安装、`controlled`、未认证；真实模式未执行模型调用，避免在未完成容器登录时产生外部副作用。
- API 端到端烟测：任务从 `in_progress` 自动入队，Runner 生成 1 次成功尝试、4 条执行事件、1 条输出，任务进入 `acceptance`。
- 完整生命周期烟测：默认方案确认任务完成 `backlog -> todo -> plan_review -> in_progress -> acceptance -> done`；返工评论重新创建执行作业并再次进入 `acceptance`。
- 宿主机未安装 `cargo`，未执行宿主机直接 `cargo check`；Rust 编译已由 Docker 构建链验证。

## 6. 交付价值

为后续真实 Agent/Codex 执行提供稳定的控制面和审计事实源，同时保持当前执行行为可控、可回溯，不会意外执行宿主机命令或修改项目代码。

## 7. 虚拟团队协作

本轮由主 Agent 完成实现、验证和文档维护，未调用角色 Agent。
