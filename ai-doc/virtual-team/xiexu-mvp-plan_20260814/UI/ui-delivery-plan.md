# 协序 MVP UI 交付计划

日期：2026-08-14
角色：UI
范围：仅规划 UI 设计交付顺序，不生成页面，不修改源码。

## 1. UI 交付节奏

### P0：设计基线与组件骨架

目标：先把全局布局、导航、状态语言和卡片结构定下来。

交付内容：
- `visual-guidelines.md`：颜色、字体、间距、图标风格、卡片密度、状态色。
- `component-map.md`：任务卡片、父子任务、评论区、状态标签、Agent 头像、进度条、运行事件、输出附件、空状态、错误状态。
- `layout-shell.md`：左侧导航、顶部栏、详情抽屉、过滤器、搜索、响应式策略。

依赖：
- PM 确认任务字段优先级和 MVP 页面入口。
- SA 确认状态名、实体关系和事件字段。

建议由 UI 先做，FE 只参与设计契约评审，不开始生产页面实现。

### P1：任务面板

目标：完成 MVP 主体验。

页面与状态：
- 看板主界面：Backlog、Todo、方案待确认、处理中、等待验收。
- 任务卡片：普通任务、项目任务、工作流任务、父任务、子任务。
- Todo 卡片“需要确认方案”勾选项。
- 父子任务展开/收起。
- 任务详情抽屉：描述、方案、评论、状态流转、子任务、运行记录、输出。
- 评论语义识别反馈：验收成功、验收失败、补充意见、返工、普通评论。
- 归档/筛选视图：done、cancelled。

复杂度：高。
FE 风险：
- 横向看板滚动与详情抽屉并存。
- 父子任务展开后列高变化。
- 实时进度和评论语义结果需要低干扰刷新。

QA 重点：
- Backlog 不触发执行。
- Todo 扫描后进入方案或执行。
- 默认需要方案确认，可单卡取消。
- 父任务验收影响所有子任务，子任务验收影响父任务部分验收。
- 返工由评论语义触发并回到正确执行阶段。

### P2：项目空间

目标：把研发视角接上同一批任务和 Agent。

页面与状态：
- 项目总览。
- 项目群聊。
- 项目任务。
- 项目文档。
- 项目 Agent。
- 项目交付物。
- 项目运行记录。

复杂度：中高。
FE 风险：
- 项目群聊生成任务时要与任务面板同步。
- 项目文档版本、刷新原因、运行记录需要共享组件。

QA 重点：
- 在项目群聊发布需求后生成任务卡片。
- 明确项目名称的任务自动关联项目。
- 父任务完成后刷新项目文档，定时任务可兜底发现遗漏。
- @ 依赖协作评论能被相关 Agent 感知。

### P3：工作流

目标：完成独立工作流模块和任务面板的运行展示。

页面与状态：
- 工作流列表。
- 工作流画布编辑器。
- 节点属性面板。
- 调度配置：周期性重复、预定时间、自然语言解析。
- 结构化调度预览。
- 运行记录。
- 暂停、恢复、终止。

复杂度：高。
FE 风险：
- 拖拽画布、节点属性、版本锁定和运行态展示需要清晰边界。
- 判断连线只做 `是` / `否`，不要做复杂规则编辑器。
- 人工确认节点依赖评论语义，不能只做固定批准/拒绝按钮。

QA 重点：
- 运行中版本不可修改。
- 暂停工作流会挂起正在运行的实例。
- 终止代表放弃。
- 工作流任务不默认要求验收，人工确认节点除外。
- 自然语言不规则时间必须以结构化形式保存和展示。

### P4：新对话与 Agent

目标：补齐单人对话、Agent 身份与固定 Agent 记忆入口。

页面与状态：
- 新对话列表与对话详情。
- Agent 选择器。
- Agent 列表。
- Agent 创建与 AI 优化。
- Agent 详情。
- 固定 Agent 记忆摘要。
- 项目固定 Agent 与动态参与 Agent 展示。

复杂度：中。
FE 风险：
- 新对话不要混入项目群聊模式。
- Agent 私有记忆文案必须解释为执行经验，不是个人隐私。

QA 重点：
- 新对话始终是 Human 与单个 Agent。
- 用户可从对话中发起任务创建。
- 自定义 Agent 可补充特定职责。
- Relay 默认 Agent 角色可展示并作为创建模板。

### P5：运行记录与设置

目标：补齐可观测性与默认配置。

页面与状态：
- 运行记录列表。
- 运行详情时间线。
- 节点运行详情。
- 输出与交付物版本。
- 设置页。
- Runner/PostgreSQL/migrate 健康状态。
- Todo 默认需要方案确认。
- Agent 扫描周期。
- 工作区路径与外部挂载说明。

复杂度：中高。
FE 风险：
- 运行记录字段多，要支持过滤和详情钻取。
- 路径映射必须清晰展示宿主机路径与容器路径。

QA 重点：
- 用户可从运行记录提取任务输出和子任务输出。
- Runner 不可用时页面展示明确错误。
- 设置项变更后影响后续任务，不 retroactively 改历史记录。

## 3. FE 设计契约建议

UI 与 FE 对齐时必须明确：
- 看板列状态枚举和不可见归档状态。
- 卡片字段的必填、可选、空值展示。
- 父子任务展开状态是否本地保存。
- 评论提交后的 AI 语义识别结果展示方式。
- 运行事件推送方式：WebSocket 或 SSE。
- 工作流画布节点和连接线的数据结构。
- 调度规则的结构化展示字段。
- 输出与交付物的预览、下载、版本展示边界。

## 4. 不纳入 MVP UI 的内容

- 权限管理页面。
- 外部注册页面。
- 公司/组织管理。
- 批量暂停、批量终止、批量迁移。
- 复杂工作流规则引擎。
- 移动端完整工作流拖拽编排。
- 自动 Git 分支、合并、提交 UI。

## 5. 当前 UI 判断

UI 首版应先压实任务面板，再做项目空间和工作流。原因是任务面板是用户理解协序的入口，也是项目任务、工作流任务、普通任务的统一展示面。只要任务面板的状态、父子关系、评论流转和运行记录入口成立，后续项目空间和工作流画布就能复用同一套组件与状态语言。
