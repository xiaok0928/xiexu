## 结论

**批准进入 M0 方案门禁。**

当前 UI/FE 契约保持了已确认的产品设计意图，没有发现阻断 M0 方案门禁的结构性问题。UI 原型、PM 评审和 FE 契约之间可以形成连续交接，FE 可以基于该契约继续参与 M0 方案设计。

本次复核没有修改 UI 原型、FE 契约或项目源码。

## 通过项

### 1. 信息架构保持分离

契约保留了以下独立入口：

- `/`：任务面板，承载独立任务、工作流和项目开发状态的可视化展示。
- `/project/:projectId`：项目空间，承载研发上下文、项目群聊、项目文档、项目 Agent 和交付物。
- `/workflow/:workflowId`：工作流，承载节点编排、运行配置和最近运行记录。
- `/chat/new`：Human 与单个 Agent 的一对一新对话。
- `/agents`、`/runs`、`/settings`：Agent、运行记录和系统设置。

这与此前确认的“任务面板面向任务可视化用户，项目空间面向研发上下文用户，两者关联但不合并”一致。契约没有回退为单一项目视图，也没有把所有协作都改成聊天流。

### 2. 任务阶段和执行状态语义正确分离

契约使用 `Task.task_stage` 决定任务卡位于哪个看板列，使用 `ExecutionJob.status` 表示执行状态，并明确阶段优先、执行状态补充展示。这符合任务面板的事实源设计，避免把“处理中”和 Agent 的 `running` 状态混为一个字段。

Backlog、Todo、方案待确认、处理中、等待验收等核心阶段均有对应展示，且保留了 Todo 默认需要方案确认、单卡片可取消的规则。

### 3. 评论驱动的任务流转已被准确表达

契约已覆盖以下评论意图：

- `plan_confirm`：确认方案，进入执行。
- `plan_revision`：补充修改意见，继续留在方案待确认。
- `accept_pass`：父任务或子任务验收通过。
- `accept_rework`：验收失败，回退到 Todo 或处理中。
- `dependency_request`、`dependency_reply`：跨子任务依赖协作。
- `note`、`question`：仅记录或提问，不改变任务状态。

同时规定无法识别时默认按 `note` 处理，避免普通评论误触发状态流转。契约没有额外增加“拒绝节点”或独立拒绝按钮，符合已确认的评论语义。

### 4. 父子任务和验收关系未被削弱

契约保留 `parent_id`、`children` 和 `child_progress`，并支持父任务展开、收缩及子任务实时进度展示。父任务验收和子任务验收可以分别触发，能够支持部分验收和返工回退。

这与 UI 原型中父任务卡片展开子任务、父任务显示聚合进度、子任务显示实时执行状态的设计一致。

### 5. 工作流独立模块的交互语义完整

工作流契约保留了：

- `start`、`end`、`action`、`decision`、`manual_confirm` 五类节点。
- 判断节点的“是 / 否”连线标记。
- 保存、运行、暂停、终止等状态操作。
- 周期性重复、预定时间、AI 解析重复规则三种调度方式。
- 不规则时间的结构化调度预览。
- 工作流运行记录和节点输出查看。

工作流不进入普通任务的验收流，人工确认通过 `manual_confirm` 节点处理，这与已确认的产品规则一致。

### 6. Agent、项目固定 Agent 和私有记忆展示方向一致

契约保留 Agent 身份、固定项目 Agent、动态协作 Agent、自定义职责和固定 Agent 执行经验记忆等字段，没有把 Agent 私有记忆错误建模为聊天隐私或用户个人备忘录。

### 7. 响应式方向与原型一致

原型在窄屏下保留模块级导航，并将看板列切换为单列选择；工作流画布保留横向滚动；详情抽屉和属性面板转为纵向布局。FE 契约明确了移动端不强制保留桌面侧栏，整体方向可实现。

## 非阻断补充项

以下事项需要在 FE 开始页面实现前或 M0 方案设计过程中补齐，但不阻断进入 M0 方案门禁：

1. **移动端项目切换入口**

   原型在移动端隐藏了最近项目侧栏，契约目前只明确保留模块切换，没有明确替代的项目切换入口。FE 实现时应在移动端顶部或任务面板筛选区提供当前项目选择器，避免多项目用户只能停留在默认项目。

2. **移动端看板列选择与深链接**

   原型已经提供列选择器，FE 契约应在实现时明确当前列是否写入 URL 查询参数或本地状态。直接打开任务详情、返回看板和刷新页面时，应保持用户所在列和当前项目上下文。

3. **工作流运行中编辑禁用范围**

   契约已区分保存、运行、暂停、终止，但 M0 方案中需要明确：工作流实例运行期间禁止修改画布结构和调度配置；只允许查看运行记录或执行实例控制。恢复操作只适用于暂停实例和暂停自动化配置的已确认场景。

4. **接口占位的字段收口**

   当前 FE 契约中的接口仍标记为“占位”。这不影响 UI/FE 交接，但 M0 方案门禁需要继续明确分页、排序、筛选、评论意图识别结果、父子任务展开数据、运行输出分页以及错误码到 UI 状态的映射。

## 复核边界

- 本次只复核 UI 设计意图、信息架构、交互语义、响应式方向和 FE 契约的一致性。
- 未复核后端接口实现、数据库结构、Agent 调度实现或 Docker 运行时。
- 未初始化 Git 或 CodeGraph，也未进行联网查询。
- 未对 UI 原型和项目源码进行修改。

## 下一步

UI 侧同意 FE 以 `ui-fe-contract.md` 作为 M0 方案设计输入，同时在 M0 方案中吸收上述四项非阻断补充项。完成 M0 方案门禁后，再进入实现阶段。
