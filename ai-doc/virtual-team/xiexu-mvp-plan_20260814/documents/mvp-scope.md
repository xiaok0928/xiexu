# 协序 MVP 范围收口

日期：2026-08-14
角色：PM
目标：将已确认能力收口为 MVP 范围，不引入新产品语义。

## 1. MVP 目标

协序 MVP 要证明一件事：用户可以在本地 Docker Web 产品中，用任务面板、项目空间、Agent 协作和工作流，把一个想法从记录推进到执行和结果沉淀。

验收时不追求复杂权限、企业组织结构、插件生态或完整代码合并自动化；只验证核心闭环是否跑通、状态是否可信、用户是否能理解正在发生什么。

## 2. Must

### 2.1 基础部署与系统

- 本地 Docker 部署。
- Web 前端。
- Rust 后端服务。
- PostgreSQL 作为唯一事实源。
- Runner 负责后台执行、任务领取、事件写入。
- 不引入 Redis。
- 支持内部用户登录和超级管理员创建账号。
- 保留创建者、所有者、审计字段。
- 首版不做功能权限和数据权限拦截。
- 账号失效不停止系统运行，不停止已创建任务、工作流定义和运行实例。
- 当运行依赖失效账号的个人凭证、个人授权或个人外部连接时，对应执行进入阻塞，等待更换凭证或转交处理。

验收结果：

- 用户可以通过本地 Docker 启动系统并进入 Web 页面。
- 系统重启后，任务、项目、工作流定义、运行记录和输出不丢失。
- 普通内部用户可以访问首版全部功能和数据。
- 账号失效后，系统级任务与工作流不被自动停止；依赖该账号个人凭证的执行会显示阻塞原因。

### 2.2 任务面板

- 提供 `Backlog`、`Todo`、`方案待确认`、`处理中`、`等待验收`、历史入口。
- Backlog 仅记录想法，不触发 Agent 执行。
- 用户手动将 Backlog 移入 Todo 后，系统才允许 Agent 扫描和认领。
- Todo 卡片默认勾选“需要方案确认”。
- 用户可在 Todo 卡片取消“需要方案确认”。
- 任务支持父子关系、展开、收起、聚合进度。
- 父任务展示上层需求和聚合进度。
- 子任务展示实时执行进度。
- 评论可表达方案通过、方案调整、验收通过、验收失败、补充说明、提及协助等意图。
- 评论意图不明确时不自动流转。

验收结果：

- 用户能创建想法并看到它停留在 Backlog。
- 用户拖入 Todo 后，任务进入可被 Agent 处理的状态。
- 需要方案确认的任务必须先进入方案待确认。
- 取消方案确认的任务可以直接进入处理中。
- Human 验收父任务时，子任务全部完成；Human 验收部分子任务时，父任务显示部分验收或聚合状态。

### 2.3 项目空间

- 用户可以创建项目。
- 项目创建后生成项目文档。
- 项目至少有一个协调 Agent。
- 项目支持项目群聊。
- 项目群聊中发布需求时，可同步生成任务卡片。
- 项目临时群聊可以关联任务。
- 项目临时群聊归档时生成总结，并写入任务记忆、项目记忆和项目文档。
- 明确项目归属的任务可自动关联项目。
- 项目文档在父任务完成后刷新。
- 系统定时检查项目文档是否可能遗漏变更，并作为兜底刷新入口。
- 支持通过评论和 `@` 触发跨任务、跨 Agent 协助。

验收结果：

- 用户创建项目后能看到项目文档、项目任务和项目群聊。
- 项目群聊中的明确需求可以形成任务卡片。
- 项目临时群聊归档后，其总结可以在关联任务、项目记忆和项目文档中查看或检索。
- 项目任务在任务面板和项目空间中指向同一份任务数据。
- 子任务 A 可以通过评论 `@` 子任务 B 或 Agent 请求协助，双方评论能沉淀在上下文中。

### 2.4 Agent 身份与协作

- 内置 Relay 风格默认 Agent 角色模板。
- 默认模板只借鉴结构和角色方向，职责说明由协序自行编写。
- 用户可以创建自定义 Agent 身份。
- 创建时 AI 可辅助优化角色职责。
- 可以为特定 Agent 补充职责。
- 项目固定 Agent 与临时动态 Agent 并存。
- 协调 Agent 负责任务拆分、指派、依赖协调、异常汇总。
- Agent 记忆按任务、项目、对话、工作流运行等上下文沉淀。
- 支持 Agent 私有记忆作为 Agent 自身长期上下文资产；首版权限开放不改变其作为 Agent 内部检索资产的产品定位。

验收结果：

- 用户能看到默认 Agent 角色模板并创建 Agent。
- 项目可以配置或拥有协调 Agent。
- 任务执行时，用户不需要手动指定每个执行 Agent。
- Agent 能基于当前任务、项目文档和必要记忆进行响应。
- Agent 私有记忆与项目共享记忆在产品语义和数据归属上可区分。

### 2.5 工作流

- 工作流是独立模块。
- 支持创建、编辑、保存工作流定义。
- 支持开始节点、结束节点、执行节点、判断节点、人工确认节点、连接线。
- 执行节点由自然语言描述任务。
- 判断节点连线明确标记“是/否”。
- 人工确认节点等待 Human 评论或确认后继续。
- 运行中的流程使用不可变快照。
- 支持手动执行。
- 支持周期性重复。
- 支持预定时间执行。
- 支持自然语言解析重复规则，并结构化存储不规则预定时间。
- 每次执行产生运行记录。
- 每次 `WorkflowRun` 在任务面板生成一个父任务。
- 执行节点生成子任务。
- 人工确认节点生成任务面板可见确认项。
- 运行记录可以查看节点状态、输出、子任务输出。
- 工作流任务默认不需要最终验收，除人工确认节点外。
- 暂停和终止可作用于自动化流程与单次运行。
- 暂停或终止自动化流程只影响未来触发，已经运行中的实例继续按自身状态执行。
- 若要影响已经运行中的实例，需要单独暂停或终止该实例。
- 首版不做错过后自动补跑。
- 首版不做批量暂停和批量终止。

验收结果：

- 用户可以保存一个包含执行、判断、人工确认节点的工作流。
- 用户可以手动触发一次运行并看到运行记录。
- 用户可以配置周期性或指定时间执行。
- 用户能在任务面板看到该次运行的父任务、执行节点子任务和人工确认可见项。
- 运行中编辑工作流定义不影响已启动的运行快照。
- 人工确认节点会暂停运行，Human 确认后继续。
- 暂停或终止自动化流程后，未来触发停止或挂起，已经运行的实例继续执行。

### 2.6 新对话

- 新对话是一对一 Human 与 AI 对话。
- 不引入第三者。
- 不自动变成群聊。
- 可以帮助用户整理想法，并在用户确认后生成任务、项目草稿或工作流草稿。

验收结果：

- 用户可以发起一对一新对话。
- AI 能根据用户描述整理成候选任务。
- 候选任务必须经用户确认后才进入任务面板。

## 3. MVP 后段里程碑

以下仍属于 MVP 产品范围，可以在 MVP 内分后段里程碑交付，不应被移动到后续大版本：

- 项目文档版本差异、回退和锁定。
- Agent 私有记忆的查看、治理和使用边界。
- 项目临时群聊归档质量优化，包括归档摘要、引用来源、写入任务记忆、写入项目记忆和更新项目文档。
- 工作流和任务的高级重试默认规则，包括默认重试次数、退避策略、超时、失败升级和人工介入。
- git worktree 可选能力，用于单人开发者或新项目的多 Agent 协作开发；公司项目仍默认不依赖 Git 分支。

验收结果：

- 项目文档可以查看版本差异，并支持回退和锁定。
- Agent 私有记忆能够被明确区分为 Agent 内部上下文资产，不与项目共享记忆混淆。
- 临时群聊归档后能可靠沉淀到任务、项目记忆和项目文档。
- 节点失败、任务失败、超时和重试耗尽时，系统有默认一致行为。
- 启用 git worktree 可选模式时，不影响无 Git 默认协作路径。

## 4. Next

以下进入 MVP 后的下一阶段，不阻塞首版闭环：

- 细粒度权限管理，包括项目权限、工作流权限、数据权限。
- 创建者账号失效后的完整转移策略。
- 更强的工作区文件隔离和 Copy-on-Write 存储优化。
- 工作流模板市场或共享机制。

## 5. Later

以下属于更远期能力：

- 外部注册。
- 公司、组织、部门、多租户管理。
- 角色权限模型。
- 插件生态。
- 自动创建公司 Git 分支、自动合并分支。
- 复杂工作流条件表达式或规则引擎。
- 批量暂停、批量终止、批量迁移。
- 多项目组合管理和跨项目资源排期。

## 6. 明确不做

MVP 明确不做以下内容：

- 不把 Backlog 自动变成可执行任务。
- 不让 Agent 跳过 Human 确认直接把想法推进到 Todo。
- 不按用户类型设计不同任务面板展示。
- 不把新对话做成多人群聊。
- 不要求用户在每个工作流执行节点手动指定 Agent。
- 不做工作流错过后自动补跑一次。
- 不把任务评论作为工作流输出的唯一事实源。
- 不复制 Relay 的角色说明原文。
- 不使用 Docker socket 动态创建任意宿主路径挂载。
- 不依赖 Redis。

## 7. MVP 总体验收

MVP 验收通过需要同时满足：

1. 用户能从新对话或手动录入创建想法，并通过任务面板推进到 Todo、方案确认、执行、验收和历史。
2. 用户能创建项目，看到项目文档、项目群聊、项目任务和协调 Agent。
3. 项目群聊中的需求能形成任务卡片，并与任务面板共享同一任务状态。
4. Agent 能基于协调 Agent 完成任务拆分、指派、评论协助和进度更新。
5. 用户能创建并保存工作流，手动或定时执行，并查看运行记录和节点输出。
6. 工作流人工确认节点能暂停流程并在 Human 确认后继续。
7. 系统在本地 Docker 环境重启后，核心数据不丢失。
8. 首版没有出现三套互相割裂的任务系统；独立任务、项目任务、工作流任务在任务面板中统一展示。
9. 每次 `WorkflowRun` 在任务面板生成父任务，执行节点生成子任务，人工确认节点生成可见确认项。
10. 暂停或终止自动化流程只影响未来触发，不影响已经运行中的实例；单次实例需要单独暂停或终止。
11. 账号失效不停止系统运行；仅依赖该账号个人凭证的执行进入阻塞。
